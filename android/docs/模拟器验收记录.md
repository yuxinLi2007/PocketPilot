# PocketPilot Android 最小原型：模拟器验收记录

- **验收日期**：2026-10-29
- **应用版本**：`0.1.0`（debug）
- **验收设备**：`PocketPilot_API34` / `emulator-5554`
- **验收范围**：Android App、模拟命令链路、手机动作执行、无障碍返回、执行状态反馈
- **验收结论**：**Android 端模拟器闭环通过；真实 BLE、ESP32-S3-EYE、实体安卓手机和语音识别尚未测试。**

> 本记录只证明 Android 配套应用能在模拟器中处理“模拟输入”。
> `FakeBleTransport`、`adb` 广播和 Mock 替代目标都不是真实 BLE，也不能作为硬件联调或真实微信/地图验收证据。

---

## 1. 验收边界

### 已验收

- Android App 可构建、安装并在 API 34 模拟器启动。
- 传输层与命令解析、校验、执行、状态记录相互分离。
- `FakeBleTransport` 可注入三条规定命令：
  - `COMMAND_OPEN_WECHAT`
  - `COMMAND_OPEN_MAP`
  - `COMMAND_BACK`
- 未安装真实微信时会明确返回 `NOT_INSTALLED`，不会伪造成功。
- Mock 替代目标可验证“命令 -> Intent -> 目标页面 -> ACK -> 已确认”链路。
- 系统地图解析器可接收 `geo:` 地址并打开 Google Maps。
- 无障碍未授权时返回 `PERMISSION_REQUIRED`；授权后可执行并核验返回。
- 非法帧、未知命令、参数缺失、参数过长、重复命令均被拒绝；目标应用或目标包不存在时返回 `NOT_INSTALLED`。

### 未验收

| 项目 | 状态 | 原因 |
|---|---|---|
| 真实 BLE/GATT 通信 | 尚未测试 | 当前没有实体安卓手机和 ESP32-S3-EYE 同场联调 |
| ESP32-S3-EYE 固件 | 部分完成 | `firmware/pocketpilot_ble` 已构建、烧录到实体开发板（COM5）并通过电脑端 GATT 契约验证；与实体安卓手机的端到端仍未验证 |
| 真实微信启动 | 尚未测试 | 模拟器未安装微信；Mock 不能替代真实微信 |
| 真实第三方地图搜索确认 | 尚未测试 | 能拉起 Google Maps，但无法确认第三方搜索结果页 |
| 语音采集与命令识别 | 尚未测试 | 本阶段没有麦克风输入、ESP-SR 或语音模型链路 |
| AI 多步骤任务 | 尚未测试 | 后续阶段目标 |
| 实体安卓手机兼容性 | 尚未测试 | 当前只有 Android Studio 模拟器 |

### 不允许的结论

- 不能把 Mock 页面显示“命令已到达”写成“微信已打开”。
- 不能把 Google Maps 被拉起写成“地图搜索结果已确认”。
- 不能把 `adb` 注入写成“真实 BLE 已通过”。
- 不能用模拟器结果替代 ESP32 与实体手机之间的无线链路测试。

## 3. 工程结构与职责

| 路径 | 职责 |
|---|---|
| `android/app` | PocketPilot Android App |
| `android/mocktarget` | 明确标注的 Mock 替代目标，不是微信或真实地图 |
| `transport/BleTransport` | 只定义收发字节的传输接口 |
| `transport/FakeBleTransport` | 模拟器专用，不连接任何蓝牙硬件 |
| `transport/GattBleTransport` | 真实 GATT 实现，保留但尚未实机验证 |
| `core/CommandCodec` | 帧编解码与协议错误处理 |
| `core/CommandValidator` | 参数、权限、重复命令校验 |
| `runtime/CommandPipeline` | 解码 -> 校验 -> 执行 -> 记录 -> 反馈 |
| `exec/*Executor` | 微信、地图、返回三类手机动作 |
| `service/PocketAccessibilityService` | 前台窗口观察与系统返回动作 |
| `debug/DebugInjectReceiver` | 仅 debug APK 存在的测试注入入口 |

关键设计：

- 传输层不理解“微信、地图、返回”的业务语义。
- 执行层不知道字节来自模拟通道还是真实 BLE。
- `FakeBleTransport.isSimulated()` 为 `true`，UI 必须显示“模拟 BLE · 非真实蓝牙”。
- Mock ACK 使用签名级权限，只接受同签名 Mock 应用回执。

## 4. 构建、安装与启动

### 4.1 设置环境并构建

在 PowerShell 中执行：

```powershell
$env:JAVA_HOME='D:\Android\jdk17'
$env:ANDROID_HOME='D:\Android\Sdk'
$env:ANDROID_SDK_ROOT='D:\Android\Sdk'
$env:Path="$env:JAVA_HOME\bin;$env:ANDROID_HOME\platform-tools;$env:ANDROID_HOME\emulator;$env:Path"

cd 'D:\个人项目\android'
.\gradlew.bat assembleDebug --console=plain
```

本次结果：

```text
BUILD SUCCESSFUL
67 actionable tasks: 67 up-to-date
```

完整构建日志：`android/docs/build-check.txt`

产物：

```text
D:\个人项目\android\app\build\outputs\apk\debug\app-debug.apk
D:\个人项目\android\mocktarget\build\outputs\apk\debug\mocktarget-debug.apk
```

### 4.2 启动模拟器

如果 AVD 已存在：

```powershell
Start-Process -FilePath 'D:\Android\Sdk\emulator\emulator.exe' `
  -ArgumentList '-avd','PocketPilot_API34','-no-snapshot-load'

& 'D:\Android\Sdk\platform-tools\adb.exe' wait-for-device
```

如果需要从零创建 AVD，先确认同名 AVD 不存在，再执行：

```powershell
& 'D:\Android\Sdk\cmdline-tools\latest\bin\sdkmanager.bat' `
  'platform-tools' 'platforms;android-34' `
  'system-images;android-34;google_apis;x86_64' 'emulator'

& 'D:\Android\Sdk\cmdline-tools\latest\bin\avdmanager.bat' create avd `
  -n PocketPilot_API34 `
  -k 'system-images;android-34;google_apis;x86_64' `
  -d pixel_6
```

不要对已有 AVD 使用 `--force`，避免覆盖既有测试环境。

### 4.3 安装并启动 App

```powershell
$adb = 'D:\Android\Sdk\platform-tools\adb.exe'

& $adb install -r 'D:\个人项目\android\app\build\outputs\apk\debug\app-debug.apk'
& $adb install -r 'D:\个人项目\android\mocktarget\build\outputs\apk\debug\mocktarget-debug.apk'

& $adb shell am start -n com.pocketpilot.app/.ui.MainActivity
```

启动后必须看到黄色提示：

```text
模拟 BLE · 非真实蓝牙
所有注入都来自进程内的 FakeBleTransport，不能作为硬件通信或真机验收证据。
```

如果没有看到该提示，不应继续把结果当作有效的模拟链路验收。

## 5. 模拟命令注入

以下入口只存在于 **debug APK**。注入广播必须显式指定包名 `-p com.pocketpilot.app`，否则 Android 14 可能不会投递给后台 manifest receiver。

```powershell
$adb = 'D:\Android\Sdk\platform-tools\adb.exe'

# 打开微信命令（当前真实微信未安装时，应返回 NOT_INSTALLED）
& $adb shell am broadcast -a com.pocketpilot.app.DEBUG_INJECT `
  -p com.pocketpilot.app --es command COMMAND_OPEN_WECHAT

# 打开地图命令
& $adb shell am broadcast -a com.pocketpilot.app.DEBUG_INJECT `
  -p com.pocketpilot.app --es command COMMAND_OPEN_MAP `
  --es argument '北京市海淀区中关村大街1号'

# 返回上一页命令
& $adb shell am broadcast -a com.pocketpilot.app.DEBUG_INJECT `
  -p com.pocketpilot.app --es command COMMAND_BACK
```

注入原始帧时，含 `|` 的帧必须交给远端 shell 解析，避免本机 PowerShell 把竖线当成管道：

```powershell
& $adb shell "am broadcast -a com.pocketpilot.app.DEBUG_INJECT -p com.pocketpilot.app --es raw 'PP2|COMMAND_BACK'"
```

### 5.1 切换 Mock 替代目标

```powershell
# 微信目标切换到 Mock
& $adb shell am broadcast -a com.pocketpilot.app.DEBUG_CONFIG `
  -p com.pocketpilot.app --es wechat_package com.pocketpilot.mocktarget

# 地图目标切换到 Mock
& $adb shell am broadcast -a com.pocketpilot.app.DEBUG_CONFIG `
  -p com.pocketpilot.app --es map_package com.pocketpilot.mocktarget

# 恢复真实微信包名
& $adb shell am broadcast -a com.pocketpilot.app.DEBUG_CONFIG `
  -p com.pocketpilot.app --es wechat_package com.tencent.mm

# 地图恢复为系统选择
& $adb shell am broadcast -a com.pocketpilot.app.DEBUG_CONFIG `
  -p com.pocketpilot.app --es map_package ''
```

Mock 页面必须显示“这不是微信，也不是真实地图”。Mock ACK 通过后，PocketPilot 会显示：

```text
已确认 · COMMAND_OPEN_WECHAT
Mock 替代目标已回执到达；这不是真实微信/地图的加载证明
```

## 6. 无障碍服务操作

### 通过系统界面

1. 打开 PocketPilot。
2. 点击“打开系统无障碍设置”。
3. 找到“PocketPilot 返回键服务”。
4. 开启服务并确认系统提示。
5. 返回 PocketPilot，确认显示“已授权，服务已连接”。

### 通过 adb 自动化

开启：

```powershell
$adb = 'D:\Android\Sdk\platform-tools\adb.exe'
& $adb shell settings put secure enabled_accessibility_services `
  com.pocketpilot.app/com.pocketpilot.app.service.PocketAccessibilityService
& $adb shell settings put secure accessibility_enabled 1
```

关闭并验证“缺少授权”：

```powershell
& $adb shell settings delete secure enabled_accessibility_services
& $adb shell settings put secure accessibility_enabled 0
```

测试结束后必须恢复无障碍服务，并确认：

```powershell
& $adb shell dumpsys accessibility | Select-String 'Bound services|Enabled services'
```

应重新出现：

```text
PocketPilot 返回键服务
Enabled services:{{com.pocketpilot.app/com.pocketpilot.app.service.PocketAccessibilityService}}
```

## 10. 云端部署能力边界

先给结论：**Android App 可以装在云端，但云手机不能替代“ESP32 + 实体手机”的 BLE 联调。**

| 场景 | 是否可行 | 说明 |
|---|---|---|
| 云手机 / 云模拟器 / 设备农场安装并运行 PocketPilot | 可行 | 云主机本质是 Android 虚拟机或远程真机，APK 可安装、可跑 UI、命令处理和状态记录 |
| 在云端验证命令管线、Mock 链路、无障碍返回、边界拒绝 | 可行 | 这些逻辑不依赖物理 BLE，`FakeBleTransport` 与 Mock 目标均可在云端工作 |
| 云端直接连接用户桌面上的 ESP32-S3-EYE 蓝牙 | 一般不可行 | 云手机没有本地蓝牙适配器；开发者无法把个人电脑的 BLE 适配器“透传”给云实例 |
| 云厂商提供 USB/蓝牙透传或本地代理 | 有条件可行 | 需要厂商明确支持的外设透传能力，且延迟、配对和权限需实测 |
| 把 ESP32 到云端改成 Wi-Fi / MQTT / WebSocket 桥接 | 可行，但性质改变 | 这时验证的已不是 BLE 链路，不能标记为“BLE 已验证” |
| 替代真实 BLE 整机验收 | 不可行 | 云端结果只能证明 App 侧逻辑，不能证明 ESP32 与手机之间的无线链路 |

判断原则：

- **云端能证明的**：App 能构建、能安装、能解析命令、能启动应用、能核验状态、能正确拒绝非法输入。
- **云端不能证明的**：BLE 配对与重连、GATT 特征读写、射频距离与干扰、ESP32 端固件行为、厂商 ROM 的无障碍差异。
- 如果用 Wi-Fi/MQTT 替代 BLE，必须在文档里写成“网络桥接链路”，而不是“BLE 链路”。

当前阶段不建议额外上云：本机模拟器已经覆盖全部可离线验证的部分，上云只会增加成本，不会增加结论强度。真实链路阶段应在同一物理现场使用实体安卓手机 + ESP32-S3-EYE。

### 11.1 真实 GATT 协议（已实现，未实机验证）

协议常量只有一处定义来源，两侧必须同步修改：

- Android：`android/app/src/main/java/com/pocketpilot/app/core/PocketProtocol.java`
- 固件：`firmware/pocketpilot_ble/main/pocketpilot_ble_main.c`

| 项目 | 值 |
|---|---|
| 广播名 | `PocketPilot` |
| Service | `6f706f63-6b65-742d-7069-6c6f74000001`（广播包携带） |
| `...0002` | 设备 → 手机，notify（带 CCCD），手机订阅后接收命令 |
| `...0003` | 手机 → 设备，write with response，手机回传执行状态 |
| 命令帧 | `PP1\|<COMMAND>\|<ARGUMENT>\n` |
| 状态帧 | `PP1\|RESULT\|<command_id>\|<STATUS>\|<detail>\n` |
| 上限 | 单帧 512 字节，地址 120 字符；超长帧整段丢弃至下一个换行并计数拒绝 |

固件工程：`firmware/pocketpilot_ble`（ESP-IDF 5.4.3，`esp32s3`）。构建与烧录：

cd 'D:\个人项目\firmware\pocketpilot_ble'
.\build.ps1                     # 源码镜像到 ASCII 路径后构建，产物复制回 artifacts\
.\flash.ps1 -Port COMx -Monitor # 需先用设备管理器确认开发板串口

串口输入单字符即可触发测试帧（与实体按键无关，仅用于无按键配置时的联调）：

### 11.2 手机端准备

1. 使用 Android 8.0（API 26）及以上、支持 BLE 外设连接的真机。
2. 安装 debug APK：

```powershell
$adb = 'D:\Android\Sdk\platform-tools\adb.exe'
& $adb install -r 'D:\个人项目\android\app\build\outputs\apk\debug\app-debug.apk'
```

3. 授予权限：附近设备（Android 12+ 为 `BLUETOOTH_SCAN` / `BLUETOOTH_CONNECT`）、通知（可选）。
4. 开启无障碍服务（返回命令必需）。

### 11.3 联调顺序（每步都要记录结果）

1. **扫描**：App 扫描到 ESP32 广播名称，记录 RSSI、配对耗时。
2. **连接**：建立 GATT 连接，记录连接耗时与首次服务发现耗时。
3. **单命令**：ESP32 按下按键发送 `PP1|COMMAND_OPEN_MAP|北京市海淀区中关村大街1号`，确认 App 收到并执行。
4. **状态回传**：确认 App 的 `command_id` 与 ESP32 端一致，形成闭环。
5. **断开重连**：强制断开 BLE 后自动重连，记录重连耗时与失败次数。
6. **距离测试**：1 m / 3 m / 5 m 各重复 20 次，统计成功率。
7. **干扰测试**：Wi-Fi 密集环境、口袋遮挡、多人环境各重复 10 次。
8. **异常**：ESP32 断电、手机蓝牙关闭、权限被撤销，确认 App 明确报错而不是卡死。

### 11.4 语音识别接入

1. 在 ESP32 端启用麦克风采集与 ESP-SR（`esp-sr` 的 MultiNet 或 WakeNet 中文模型）。
2. 确认模型与 ESP-IDF 版本、Flash/PSRAM 配置兼容。
3. 识别结果映射为三条命令之一，发送同一套 `PP1|...` 帧。
4. 记录识别正确率：安静环境、3 m 距离、背景噪声三种条件各 50 次。

### 11.5 验收口径

- 只有**实体手机 + 实体 ESP32 + 真实无线链路**同时满足，才能把“BLE 链路”标为通过。
- 语音识别必须有实测正确率，不能只凭“能识别一次”就写通过。
- 任何未实测项在 README 与验收记录中继续保持“尚未测试”。
