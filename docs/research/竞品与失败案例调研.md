# PocketPilot 竞品与失败案例调研

> 版本 v1.0 ｜ 2026-10-28 ｜ 阶段：T0 通道穿刺之前
> 范围：安卓手机 + ESP32-S3-EYE + BLE HID。iPhone 不在本轮开发与验收范围。
> 目的：回答三个问题——(1) 这条路上已经有哪些人做过、结果如何；(2) 我们的差异化到底成不成立；(3) 对当前最小原型有什么直接影响。

---

## 0. 结论先行

1. **L1（语音 → 媒体键）没有产品差异化，只能当通道穿刺。** 蓝牙耳机、手表、自拍快门、手机自带语音助手都能实现类似效果。它的价值是低成本排除"板子能不能稳定控制手机"这个技术风险，不是证明产品。
2. **L2（语音 → 安卓系统级操作）差异化"弱成立"。** 能力本身不稀缺：Tasker、MacroDroid、AutoJs6、无障碍脚本都能做。真正可能稀缺的是"可确认、可停止、可审计"的安全执行层，以及一个高频、具体的场景。
3. **L3（AI 多步任务）差异化"尚未证明"。** Rabbit R1 从"代操作 App"退到"第三方 Agent 高度实验性"，说明最后一公里（登录、验证码、UI 变化、失败恢复）比演示难一个数量级。
4. **最大的威胁不是另一个硬件，而是手机自带助手 + 开源小智生态。** 前者免费且预装；后者把"ESP32 语音盒子"做成了 3 万星的 MIT 开源项目。硬件本身没有壁垒。
5. **对 T0 的要求不变：** 先证明"板子 → 主流安卓"这条通道稳定，再谈语音和产品。T0 不通过，后面全部不做。

> 一句话判断：**现在还不能说"差异化成立"，只能说"有一个值得验证的窄场景假设"。** T0/L1 的职责是排雷，不是证明商业价值。

## 4. 三个受挫案例深挖

### 4.1 Humane AI Pin：把"替代手机"当成最小原型

**已核实的事实**

- `humane.ai` 当前已不再提供产品页，访问会跳转到 `/lander`（域名停放页）。
- 二手报道口径：惠普（HP）于 2025 年 2 月以约 **1.16 亿美元**收购 Humane 的资产；AI Pin 停止销售，并于 **2025-02-28** 停止云服务。
- 公开报道口径：AI Pin 发售价约 **$699**，另需 **$24/月**订阅（未取得官网原文，标 D）。

**失败链条（按因果顺序）**

1. **价值主张过宽**：对外承诺"替代手机"，而不是解决一个具体高频任务。
2. **交互反人性**：激光投影在户外、强光、手抖场景下可用性差；抬手腕/点投影的操作成本高于掏手机。
3. **重云依赖**：识别、回答、服务都依赖云端；延迟、发热、续航、断网体验一起恶化。
4. **价格与订阅错配**：$699 + 月费，用户会拿它和"免费手机 + 免费助手"比较。
5. **口碑与退货**：体验不达预期后，负面评价放大；最终停售、停服，设备变成"砖"。

**对我们的映射**

- T0 不要追求"全能"，只验证 6 个媒体键。**最小原型的目的是排雷，不是演示未来。**
- L2 的产品叙事不能写"替代手机"，只能写"在某些场景下比手动操作更省事/更安全"。
- 任何依赖云的核心能力，都必须设计**服务终止后的降级路径**（至少本地命令仍可用）。

### 4.2 Limitless Pendant：有真实价值，也可能被合规与平台吸收

**已核实的事实（官网公告）**

- Limitless 已被 **Meta 收购**。
- 自 **2025-12-05** 起不再向新客户销售 Pendant。
- 现有 Pendant 客户的支持持续到 **2026 年**；老用户不再需要付费订阅，获得 Unlimited Plan。
- 自 2025-12-05 起，服务在 **巴西、中国、欧盟、以色列、韩国、土耳其、英国** 不再提供；用户须在 2025-12-19 前导出数据。
- 非 Pendant 功能（如 Rewind）停止：Rewind 于 2025-12-19 起停止屏幕与音频捕获。

**失败链条**

1. 产品有真实价值（会议记录、回忆、检索），不是"伪需求"。
2. 但"always-on 录音"带来**隐私、数据合规、区域监管**成本，且成本随市场扩大而上升。
3. 被平台巨头收购后，独立产品线结束；硬件停止销售，服务收缩。
4. 用户买的是硬件，实际拥有的却是"随时可能被终止的服务"。

**对我们的映射**

- 默认**不保存完整音频**、日志脱敏、端侧优先，这些不是"加分项"，是这类产品的**生存底线**。
- 如果未来做录音/转写，必须提前回答：数据存在哪、保存多久、如何删除、哪些地区不能卖。
- "被收购"不是成功模板；对单人项目，**可持续的现金流**比"被巨头看中"更现实。

### 4.3 Rabbit R1：通用 Agent 的最后一公里

**已核实的事实（官网）**

- 售价 **$199**，**无订阅**，运行 Rabbit OS3，定位为"进入 OS3 的原生物理入口"。
- 官网明确写明：**第三方 AI Agent 是高度实验性的（highly experimental）**，不由 Rabbit 开发或维护；用户必须自行配置，风险自负；Rabbit 不为其性能、可靠性、行为或数据安全负责。

**受挫点（结构性，不是单次事故）**

1. 早期叙事是"LAM 代替你操作 App"，但真实世界的 App 有登录、验证码、风控、频繁改版、弹窗。
2. 通用 Agent 的可靠性不是"模型更聪明"就能解决，而是**每个 App 的最后一公里工程**。
3. 最终把跨 App 能力交给第三方 Agent，并在法律文本里标注"高度实验性"——这等于承认通用代操作尚未产品化。
4. 硬件低价（$199）意味着必须靠生态/服务变现，但生态尚未闭环。

**对我们的映射**

- L3 只做**一个窄任务闭环**（例如"从消息里取地址 → 打开地图 → 搜索 → 确认结果"），不做"任意 App 任意操作"。
- 每个任务必须有：**可验证的成功条件 + 失败恢复 + 用户确认**。否则就是演示，不是产品。
- 不要用"支持多少个 App"做指标，用"单任务成功率、平均完成时间、失败后可恢复率"做指标。

### 4.4 三个案例的共同模式

| # | 共同问题 | 具体表现 | 对我们的红线 |
|---|---|---|---|
| 1 | 价值主张过宽 | "替代手机"/"万能助手" | 最小原型只承诺一个场景 |
| 2 | 重云依赖 | 断网/停服即失效 | 核心命令必须本地可用 |
| 3 | 交互反人性 | 投影、无屏、手势学习成本 | 按键触发，符合既有习惯 |
| 4 | 价格/订阅错配 | 硬件贵 + 月费 | 先证明价值，再谈订阅 |
| 5 | 跨 App 最后一公里 | 登录/验证码/UI 变化 | 窄场景 + 可验证 + 失败恢复 |

## 5. 我们的差异化到底成不成立

### 5.1 分三层判断

| 层级 | 我们想做的 | 已有替代 | 差异化 | 判断 | 成立条件 |
|---|---|---|---|---|---|
| **L1** | 语音 → 音量/播放/下一首 | 蓝牙耳机、手表、快门、手机助手 | 无 | **不成立** | 只作为通道穿刺，不作为产品 |
| **L2** | 语音 → 返回/主页/打开 App/拨号 | Tasker、MacroDroid、原生助手、无障碍脚本 | 弱 | **条件成立** | 安全执行层 + 特定人群 + 可审计 |
| **L3** | 语音 → 多步任务（地址→导航） | Rabbit、手机助手、人工操作 | 未证明 | **待验证** | 单任务闭环 + 可验证 + 失败恢复 |

### 5.2 唯一可能的护城河（四条，缺一不可）

1. **物理按键的确定性**：按下去才听，没有误唤醒；隐私感强，适合卧室/会议/老人。
2. **安全执行层**：高风险动作二次确认、全局停止 ≤300 ms、每一步有日志、可回放。
3. **场景纵深**：锁定一个"手机操作确实困难"的人群，而不是"所有人"。
   - 候选：老人/无障碍用户、骑手/司机、单手抱娃的家长、戴手套的户外工作者。
4. **离线优先**：常用命令不联网；云只用于复杂任务，且可一键关闭。

> 这四条没有一条能在 L1 被证明。L1 只能证明"通道通"；L2 才能证明"安全执行层有价值"；P 阶段（5 人试用）才能证明"有人愿意用/买"。

### 5.3 如果只能选一台参考机：为什么是安卓

| 维度 | 安卓 | iPhone | 对本项目的含义 |
|---|---|---|---|
| 系统级返回/主页 | `AccessibilityService.performGlobalAction()` 支持 `GLOBAL_ACTION_BACK` / `GLOBAL_ACTION_HOME`（API 16+，官方文档） | 无开放等价接口 | L2 只能在安卓成立 |
| 跨 App 操作 | 无障碍可读界面、模拟点击 | 仅 App Intents/快捷指令，且需 App 主动开放 | 产品上限差一个层级 |
| Windows 上开发 | Android Studio/adb 全流程 | 必须 macOS + Xcode | 当前环境只能安卓 |
| 安装测试版 | 直接装 APK | 需签名，免费账号 7 天失效 | 迭代成本差数倍 |
| 媒体键（L1） | 标准 BLE HID 可用 | 标准 BLE HID 也可用 | L1 两平台都能做，但不是选择依据 |

**结论：** 如果目标是"语音操控手机"而不是"语音控制我们自己的 App"，参考机必须选安卓。iPhone 版本只有在"目标用户 70% 以上是 iPhone"且"功能缩减为媒体键 + 自有 App"时才值得重做。

### 5.4 最终判断（写给自己看）

> **"差异化成立"目前不成立，它是一个待验证假设。**
>
> 只有当以下三件事同时发生，才可以改口：
> 1. T0 通过：主流安卓上 6 个媒体键稳定，锁屏后台音乐场景可用；
> 2. L2 做出"确认—执行—验证—停止"闭环，且高风险动作绕过确认 = 0；
> 3. 5 人试用中，至少 3 人表示"在特定场景下比手动快 30% 以上，并愿意继续用"。
>
> 在此之前，所有"AI 助手""替代手机""万物控制"的表述都应删除。

## 6. 对 T0 / L1 的直接影响

### 6.1 命令集

- **只保留 6 个媒体键**：音量 +、音量 −、播放/暂停、下一首、上一首、静音。
- **不加**"返回/主页/打开 App"——这些是 L2 的无障碍能力，HID 没有。
- **不加**"语音唤醒"——T0 阶段只验证通道，语音在 L1 才进入。

### 6.2 指标

- 只看四个数：**真实响应成功率、延迟中位数、5 秒内重连率、板子发送失败次数**。
- 不看"演示是否流畅"、不看"朋友觉得酷不酷"。
- 锁屏无媒体会话时，媒体键可能被系统吞掉——这是系统行为，要记录，不要当成蓝牙 bug。

### 6.3 失败预案

| T0 结果 | 解释 | 下一步 |
|---|---|---|
| 6 键在 unlocked 下 ≥4 条通过 | 通道基本可用 | 进入 L1 |
| 只有音量键可用，媒体键全挂 | 报告描述符/ROM 兼容问题 | 先修 HID 描述符，再复测；仍失败则考虑 GATT + App |
| 锁屏后台音乐场景 <2 条通过 | 系统省电/媒体会话限制 | 记录机型；L2 用 App + 前台服务兜底 |
| 连接 5 秒内重连 <5/10 | BLE 参数/配对问题 | 调连接间隔、绑定信息、重连策略 |
| 出现必须拔电才能恢复 | 固件稳定性问题 | 一票否决，先修稳定性 |

### 6.4 竞品启示（一句话版）

- **不要做"通用语音助手盒子"**——小智 AI 已经免费开源，手机助手已经预装。
- **不要用"支持 App 数量"讲故事**——Rabbit 的教训。
- **不要把"录音"当默认卖点**——Limitless 的合规成本。
- **如果 L1 只是媒体控制，产品叙事必须是"特定场景的物理快捷键"**，不是"AI 硬件"。

## 9. 一页纸摘要（给未来的自己）

- **市场不缺"语音助手"，缺的是"在特定场景下确实更省事、且不会闯祸的执行工具"。**
- **L1 只是通道穿刺，不是产品。** 媒体键谁都能做，做完只能证明"板子能控制手机"。
- **L2 才有产品雏形，但必须绑定"确认 + 停止 + 日志"三件套。**
- **L3 只做单任务闭环，不做通用 Agent。** Rabbit 已经把"通用"的坑踩给我们看了。
- **最大的竞争压力来自免费：手机自带助手 + Tasker/MacroDroid + 小智开源生态。**
- **当前结论：差异化未成立；T0 先证明通道，L2 再证明价值，P 阶段再证明有人愿意买单。**
