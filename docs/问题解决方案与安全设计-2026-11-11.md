# PocketPilot 问题解决方案（2026-11-11 辩论收官）

> 来源：2026-11-11 五方辩论（硬件工程 / Android 系统 / 老年用户研究 / 投资人 / 安全合规）。
> 本文逐条给出解决方案与验收标准。**财产安全为最高优先级，已在代码层落地。**

## 一、财产安全：多层硬防守（已落地代码 + 全部命令禁令）

### 1.1 总原则

**PocketPilot 在任何阶段、任何版本，都不提供任何支付、转账、金钱操作能力。**
这不是"暂缓上线"，而是产品定义的一部分：老人按住说话，设备只能做"安全的确定性动作"。

### 1.2 六层防守体系（第 0-5 层全部落地）

| 层 | 位置 | 防守内容 | 状态 |
|-|-|-|-
| L0 设备端 | ESP-SR 命令词注册表 | **从不注册**任何支付类词条（付款/转账/红包等），语音入口物理上不存在 | ✅ 注册表只有 3 命令 |
| L1 协议层 | `CommandType` 枚举 | 协议中不存在 PAY/TRANSFER/SEND_MONEY 类命令，BLE 帧层面无此表达 | ✅ 只有 4 种命令 |
| L2 白名单层 | `ActionPolicy.ALLOWED` | 默认拒绝制：白名单只有 OPEN_WECHAT/OPEN_MAP/BACK，新增动作须走评审 | ✅ 已有 |
| L3 敏感层 | `ActionPolicy.SENSITIVE` | 恒为空：不可逆动作连"确认后执行"的资格都没有，无任何绕过路径 | ✅ 已有 |
| L4 文本层 | `FinancialGuard`（新增） | 对话语和计划步骤参数做财产关键词+金额模式拦截，防诈骗话术、防绕过 | ✅ **本次新增** |
| L5 校验层 | `PlanValidator`（已接入） | 所有规划器（规则/云端/未来任何实现）输出必须过 L4，拒绝码 `FINANCIAL_CONTENT_DENY` | ✅ **本次接入** |
| L6 执行层 | `ExecutorRegistry` | 不存在任何支付执行器，白名单之外无代码路径 | ✅ 已有 |

### 1.3 FinancialGuard 拦截规则（代码：`android/.../plan/FinancialGuard.java`）

- **关键词表**（60+ 条）：支付/付款/转账/转钱/汇款/红包/付款码/收款码/密码/验证码/银行卡/余额/花呗/借呗/免密/理财/基金/股票/充值/提现/退款/… + 英文 pay/transfer/password/bank/wallet 等
- **金额模式**：数字+货币单位（元/块/万/千…），覆盖口语变体（"汇500块给他"）
- **防绕过归一化**：全角转半角、去空白、去标点、统一小写——"转 账""转，账""ｐａｙ"全部拦截
- **fail-safe**：守卫自身异常时按"拒绝"处理，绝不能因异常放行
- **不可配置**：无开关、无覆盖标志，任何代码路径都无法绕过

### 1.4 反诈骗专门设计（合规方"诈骗执行器"质疑的回应）

| 场景 | 防守 |
|-|-|
| 电话中骗子指挥老人"对着设备说转账" | L0 根本听不懂 + L4 文本拦截，双重失效 |
| 骗子让老人念"验证码" | L4 拦截"验证码"关键词，App 播报"涉及金钱的操作请让家人帮忙" |
| 骗子要求"打开支付软件" | 白名单里没有支付类 App，规划器无法产出 |
| 骗子要求读消息里的地址/内容 | 无障碍权限仅限 BACK，永远不读屏幕内容（隐私红线不变） |
| 子女代配置"自动付款任务" | 产品根本不存在此类任务类型，配置界面无从配置 |

**播报话术（被拦截时）**："这个操作涉及钱，我不能做。涉及钱的事，请让家人帮忙。"

### 1.5 回归验证

`android/tools/planner-selftest/PlannerSelfTest.java` 新增 `financialGuardTests()`：
13 条拒识用例（含空格/标点/全角/大小写/金额模式绕过）+ 6 条放行用例 + 4 条校验层集成用例
（含"给了确认也拒绝""步骤参数层拦截"）。**财产安全防线必须随每次回归一起验证。**

## 二、辩论问题逐条解决方案

### 问题 1：拾音姿势矛盾（麦在背面，人朝屏幕说话）

**方案**：① 设备顶边斜面麦口朝向按"手持看屏幕"姿势校准（麦指向手机屏幕侧）；
② "取下即遥控"升级为一等场景：手机放桌上、设备拿在手里说，App 通过手机扬声器
播报结果——这正是产品文档里"桌面伴侣"形态，无需改硬件。
**验收**：真机测试中"手持看屏幕姿势"识别率 ≥90%（每命令 10 次）。

### 问题 2：按住说话 vs 老人手抖（双任务冲突）

**方案**：按下瞬间开始环形预录（不依赖唤醒词）+ 松手后 0.5s 宽容窗才截断 +
按下即"叮，请讲"提示。保留"按住说话"为主模式（防误触发优先），
"单击+5 秒说话"作为手抖用户在 App 里的可选模式（默认关闭）。
**验收**：老人实测"从按下到说完"全程成功 ≥85%，中途松手不丢关键字。

### 问题 3：固定命令词听不懂变体

**方案**：变体注册从 3 条/命令扩到 10-20 条/命令（"整开""弄一下""我要看地图"等
口语说法）；L2 端侧小模型继续按原计划排期，但**先收集真实失败话语日志再训**，
不做无数据的新增。拒识时 App 播报"没听清，可以说：打开微信"给出标准说法示范。

### 问题 4：无障碍权限被 ROM 重置 → 产品"无声失灵"

**方案**（首版必做）：App 三重自检——
① 开机自启动后 10s 内检查无障碍授权 + 后台锁定状态，异常时手机大字弹窗；
② BLE 断开 >5 分钟且重连失败 → 推送子女"爸妈的设备连不上了"；
③ 自检结果写入 results.jsonl（`SELF_CHECK` 事件），Lab 监测站可见。
**验收**：模拟器上人为关闭权限后，1 分钟内子女端收到提醒。

### 问题 5：国产 ROM 杀后台 → BLE 永远连不上

**方案**：配置流程第 2 步做成图文引导"锁定后台 + 关闭电池优化"（分机型截图指引，
MIUI/EMUI/ColorOS 各一套）；固件侧检测连接断开 >N 分钟主动红闪提示老人；
设备端 LED 慢闪表示"未连接"，老人能看懂"现在不可用"。

### 问题 6：首版价值密度（3 命令配 199-299？）

**方案**：**预设键拨号升级为首版核心卖点**（辩论采纳项 #3 的落地）——
子女在 App 配置"长按侧键 1 = 打给女儿"，设备端只需存一个号码 + 拨号命令
（技术上 L1 即可实现，协议新增 `COMMAND_DIAL`，参数=预设槽位号，真实号码
不进协议帧、不进日志）；按住主键说话的 3 命令保持不变。
**验收**：从"拿起设备"到"电话拨出"≤5 秒，零语音依赖。

### 问题 7：跟免费替代品竞争

**方案**：演示铁律——"飞行模式 + 65 岁以上真人 + 不教措辞"。任何宣传素材里
出现年轻人操作一律重拍。差异化只打三件事：零唤醒、离线、方言兜底。

### 问题 8：BACK 在微信里可能帮倒忙

**方案**（已落地代码）：`BackExecutor` 返回安全白名单状态机——
只对已知应用（微信/三大地图/启动器/自家应用）发送返回；未知界面**拒绝执行**并
语音播报"这个页面不能返回，请让我看看"；前台包名无法获取时同样拒绝。
**验收**：模拟器回归中 BACK 在非白名单应用返回 REJECTED 且不产生任何按键动作。

### 问题 9：4.2mm 塞不下（硬件工程师的物理账）

**方案**：3D 打印手板**同时打 4.2 和 5.5 两个厚度**，让老人的手和天线实测投票；
对外话术不再承诺具体厚度数字，改为"比银行卡略厚"。
**验收**：手板握持测试 + 铝盖天线 OTA 实测（掉值 <5dB）双通过后锁死厚度。

### 问题 10：续航口径（40-60mA 常开 7 小时见底）

**方案**：对外口径改为"≥5 天待机 / 每天 10 次可用"（按住才工作 + 深睡占空比）；
实测前任何宣传材料不出现"续航 X 天"具体数字，改为"一次充电用一周*（实测中）"。

### 问题 11："完整手机 Agent"的边界

**方案**：定位改写为**"受约束的手机 Agent"**——只做预编排短路径（开应用、拨号、
导航、固定控件），跨 App 自主操作不承诺，失败即认输不硬撑；
敏感操作三步确认（设备提示 → 手机大字显示 → 实体确认），**支付/转账类默认关闭
且永不开放**（见第一节）。

### 问题 12：商业模式单一（卖硬件 LTV 只有单次）

**方案**：首批定价 399 验证价格上限；非硬件收入 = 子女端服务（远程配置 +
使用周报 + 异常提醒，年费 49-99）；渠道优先级：子女线上内容种草 → 机构采购
（养老院/社区）→ 运营商合约。

## 四、安全设计不变式（写死在代码注释与文档中）

1. 财产类能力**永不出现在**：命令词注册表、协议枚举、白名单、执行器注册表、配置界面。
2. 任何新增功能必须先问：**"这个功能能不能被用来把钱从老人手里转走？"**——能，就不做。
3. 拦截永远 fail-safe：防守代码自身故障 = 拒绝，不是放行。
4. 统计口径公开：Lab 监测站展示 `FINANCIAL_CONTENT_DENY` 拦截次数，防线被攻击的
   次数本身就是产品价值证据。
