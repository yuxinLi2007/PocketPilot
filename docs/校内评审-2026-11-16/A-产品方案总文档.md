## A. 产品定位与用户价值（产品经理 + 投资人）

### A.1 产品究竟是什么

一块吸在老人手机背面的**实体语音按键**，配合一个 Android App。老人按住按键说话，设备本地识别成命令，通过蓝牙发给手机，手机执行（打开微信/地图、返回上一页、拨打预设电话），并把结果用语音播报出来。🟢

用投资人听得懂的话：**它把"语音助手"从云端黑科技降维成"老年人能用的遥控器"**——竞争力不在 AI 多强，而在交互路径短到不需要学习。

### A.2 解决什么具体问题、谁最需要

- 具体问题：老人使用智能手机时"找不到图标、记不住步骤、怕按错扣钱"三大障碍；子女远程指导成本高。
- 最需要的人：65 岁以上、视力和精细操作能力下降、但仍有出行/社交需求的老人；付费决策者是 30-45 岁子女。
- ⚠️ **诚实标注**：痛点目前来自产品假设与生活观察，**无问卷、无访谈数据**。评审前建议补 5-10 人快速访谈（见基线矛盾清单 #6）。

### A.3 为什么不用现有产品（差异化是否有实质支撑）

| 替代品 | 为什么不够 | 我们的实质差异 | 支撑证据强度 |
|-|-|-|-|
| 手机自带语音助手（Siri/小爱/小艺） | 要喊唤醒词、离线能力只在新旗舰机、方言弱、无实体键 | 按住即说（零唤醒）、中低端旧机可用、实体大键可盲按 | 强——交互层差异，可被现场演示证明 |
| 智能音箱（小爱音箱等） | 不能带出门、不能操作手机 | 随身、直接驱动手机执行 | 强 |
| 老人模式桌面 App | 只是图标变大，流程步数没少 | 把多步流程压缩成一句话 | 中——需实测验证压缩效果 |
| 快捷指令/NFC 贴纸 | 配置门槛高，老人自己不会配 | 子女一次配置，老人零配置 | 中 |

⚠️ 差异化中最弱的一条是"方言兜底"——**目前方言零测试数据**（基线矛盾 #3），汇报时不得作为已实现能力。

### A.4 核心使用场景与完整流程

**场景 1（最重要）：想给女儿打电话。** 拿起设备 → 长按预设键 1 → 手机跳到拨号盘、号码已预填 → 老人按一下绿色拨号键拨出。到拨号盘 ≤5 秒、不用说话、不用翻通讯录；**最后一下确认是刻意保留的防误拨设计**（不自动拨出，遵循执行任务书第 175 条）。🟡（COMMAND_DIAL 待开发，属首版核心）

**场景 2：想视频看孙子。** 按住绿键说"打开微信" → 设备识别 → 手机打开微信并播报"已打开微信"。🔵（设备侧+模拟器侧已分别验证，真机端到端待测）

**场景 3：找不到返回。** 按住说"返回" → 手机执行返回；若当前界面不在安全白名单，拒绝并播报"这个页面不能返回"。🟡（白名单代码已写，Android 运行时未验证）

**使用前**：子女 10 分钟完成贴膜/装 App/开权限/配对/配置预设（🟡 自检引导待开发）。
**使用中**：只有"按住说话"一个动作；失败必有语音+灯光+震动反馈。
**使用后**：App 记录使用日志，异常时推送子女（🟡 待开发）。

### A.5 用户是否愿意付费

诚实回答：**未知。** 399 元是假设的价格上限验证点，不是调研结论。校内评审阶段不需要回答"市场多大"，只需要回答"我打算用什么实验验证付费意愿"（答：首批小批量预售/社区试用付费率）。

## B. 产品功能与交互（产品经理 + 软件）

### B.1 功能分级

| 层级 | 功能 | 状态 | 说明 |
|-|-|-|-|
| **MVP 必须有** | 按住说话→识别 3 命令→BLE 发送→手机执行→状态回传+语音播报 | 🟡 真机端到端未通 | 没有它就没有演示 |
| **MVP 必须有** | 财产安全六层防守 | 🔵 已实现 | 项目底线 |
| **MVP 应该有** | 预设键拨号 COMMAND_DIAL（**双入口**：物理预设键 + 语音说"打给女儿"等称呼命令词，路由到同一命令） | 🔴 待开发 | 价值密度关键（问题 6 决议 + 2026-11-18 决策表 #21） |
| **MVP 应该有** | 权限/连接三重自检 + 子女提醒 | 🔴 待开发 | 防"无声失灵"（问题 4/5） |
| **首版迭代** | 命令词变体扩充（每命令 10-20 条口语说法） | 🔴 待开发 | 数据驱动，先收失败日志 |
| **未来迭代** | L2 端侧小模型（任意句式理解） | 🔴 未启动 | 由真机失败率数据决定是否做 |
| **未来迭代** | L3 云端大模型（多步骤任务） | 🔴 未启动 | PlannerStub 预留接口 |
| **不做（红线）** | 支付/转账/读屏内容/发消息 | 🟢 永久不做 | 六层防守写死 |

### B.2 启动/操作/取消/结束

- 启动：按住主键（≥300ms 长按门槛，低于视为误触静默忽略）。
- 取消：松手即结束录音；执行中无中途取消机制（命令本身是瞬时动作，风险低）🟢。
- 结束：手机执行 → 六态状态机回传 → 灯/震/语音播报。

### B.3 异常情况处理（逐项）

| 异常 | 处理设计 | 状态 |
|-|-|-|
| 语音识别失败 | 红闪+震动，手机播报"没听清，可以说：打开微信"（示范标准说法） | 🟡 播报链路待真机 |
| 蓝牙断开 | 自动重连；>5 分钟失败推送子女；设备 LED 慢闪提示"不可用" | 🟡 重连代码有，真机未测；推送待开发 |
| 网络断开 | L1 命令不依赖网络；地图等目标应用自身需要网络时由应用提示 | 🟢（架构上天然解耦） |
| 手机未装目标 App | 返回 NOT_INSTALLED，播报"微信未安装" | 🔵 模拟器已验证 |
| 无障碍未授权 | 返回 PERMISSION_REQUIRED，绝不静默失败 | 🔵 模拟器已验证 |
| 误触 | 物理六条（凹槽/围堰/长按门槛等）+ 300ms 软件门槛 | 🟡 无实物实测 |
| 误识别 | 拒识优先于错执行（无声拒识已验证🔵）；变体扩充降低拒识率 | 🟡 |
| 重复执行 | command_id 幂等去重，重复帧拒绝 | 🔵 已实现 |
| 错误执行 | 白名单默认拒绝 + 执行结果核验（区分"已执行/已确认"） | 🔵 模拟器已验证 |

### B.4 应该删减的功能

评审组主动建议删减/后置：
1. **Pro 版 0.96" 屏幕 + 设备端喇叭**——违背"交互路径最短"原则，成本厚度双升，建议从规划中淡化。
2. **双击重放上次任务**——使用频率存疑，且增加误触面，建议真机数据出来前不作为宣传功能。
3. **"取下即遥控"桌面伴侣场景**——保留（零成本场景延伸），但不单独宣传。

## C. 硬件系统（硬件工程师逐项审查）

### C.1 主控芯片

- **为什么需要**：要跑离线语音命令词识别（需要带 AI 向量指令的 MCU）+ BLE 协议栈 + 按键/音频采集。
- **可选方案**：① ESP32-S3（现用开发板，固件已验证）② ESP32-S3-PICO-1 SiP（商业化，0.96mm 高）③ nRF52 等纯 BLE SoC（跑不了语音，放弃）④ 国产低成本 SoC（识别方案要重做，远期再议）。
- **推荐**：原型继续 ESP32-S3-EYE（已有、已验证）；商业化 ESP32-S3-PICO-1（同家族固件零改动，乐鑫官方规格书佐证）。🟢
- **成本/难度**：SiP 约 ¥25-35/颗（估算）；难度低（家族内迁移）。适合 MVP：✅（原型免费沿用）。
- **风险**：PICO-1 供货与价格——备选 MINI-1 模组（2.4mm 高，机身需加厚，已不在 5.5mm 口径内，若启用需重新核算）。🟡

### C.2 麦克风及音频采集

- **为什么需要**：按住说话的入口。
- **方案**：MEMS 数字麦（高约 1.0mm），I2S 接口。原型已修复 24bit 字节对齐问题（拍手 rms 42→481，11.5 倍信号验证）🔵。
- **商业化风险**：5.5mm 薄机身拾音腔体变浅 → 方案为侧向短声道 + 硅胶密封圈补偿。🟡 未实测，列入手板验证。
- **兼容性注意**：麦口位置与磁吸面、按键"控制岛"的布局冲突已在 v2.3 设计中规避（麦口在顶面斜面、控制岛同端）。

### C.3 电池与电源管理

- **为什么需要**：无源设备，目标 5 天以上续航。
- **方案**：250-300mAh 薄型锂电（3.0mm 标准厚度）；功耗模型 = 深度睡眠 + 按键唤醒 + BLE 低功耗连接，语音识别峰值约 300mA 但占空比 <5%（按住才工作）。
- **诚实标注**：6-8 天续航是**估算**，依据是占空比推算，**无任何实测**；原型开发板目前是 USB 供电，**深度睡眠固件尚未开发**🔴。这是"原型能力 ≠ 商业化能力"的典型例子。
- **充电**：USB-C + 底座 pogo 双路。USB-C 座 3.2mm 是厚度硬约束（正是它决定了 5.5mm 而非 4.2mm）。
- **安全**：锂电池需过充/过放保护板（BMS），底座触点防反接。认证时电池需单独过检（见 H 节）。

### C.4 蓝牙通信

- **方案**：BLE GATT 自定义服务（已验证 MTU 185、分片重组、幂等）🔵。
- **⚠️ 评审组主动发现的问题**：当前协议设计文档中**未见配对绑定（bonding）与链路加密**的描述。理论上范围内任何手机都能扫描到 "PocketPilot" 广播并尝试连接写入。虽然有命令校验和内容护栏兜底，但**缺少链路层认证是真实的安全缺口**。
- **建议**：商业化固件启用 BLE 配对绑定 + 加密连接（ESP-IDF 原生支持，工作量约 1-2 周）；MVP 演示阶段可暂缓，但**专家问答必须能答上来**（见答辩库 Q17）。
- 为什么不选 WiFi/经典蓝牙：BLE 功耗低一个量级，命令帧只有几十字节，WiFi 是杀鸡用牛刀。🟢

### C.5 按键及交互器件

- 主键 Ø12 凹槽内嵌（低于表面 0.4mm）+ 围堰护圈 + 预设键 ×2（凸点盲文区分）🟡 设计定稿无实物。
- 状态反馈：主键透光 LED（苔绿/暖白/砖红语义）+ 线性马达。🟡
- **风险**：老人手抖 vs 300ms 长按门槛 → 已有预案（环形预录 + 0.5s 宽容窗 + 可选"单击+5 秒"模式）🔴 待开发待实测。

### C.6 PCB 设计

- 商业化自研 PCB：双面板即可，器件单面布局（电池与主板并排，取层内最大值——这是 5.5mm 的来源）。
- 继承教训：I2S 24bit 时序、麦克风偏置电路布局直接吸收原型踩坑记录。🟢
- 难度：对学生团队中等；建议首款手板 PCB 用嘉立创打样（¥100 级，估算）。

### C.7 天线设计

- 核心约束：**铝盖屏蔽 2.4GHz**——铝只做正面外观盖，IFA 天线（一种 PCB 印刷天线）放塑料背壳远端，净空区远离电池/磁铁/隔磁片。🟢 设计原则
- 验收门槛：OTA 实测掉值 <5dB（对比原型基线 RSSI −36dBm@1m）。🟡 未实测——**这是手板阶段的生死项**。

### C.8 散热与功耗

- 峰值 300mA（识别时），占空比 <5%，铝盖兼作散热面。🟢 设计合理，风险低。

### C.9 结构堆叠（与 E 节联动）

5.5mm 堆叠账：USB-C 3.2 + PCB 0.8 为局部最高点；电池 3.0 与主板并排；铝盖 0.6 + 背壳 0.9 + 磁铁槽 0.3 + 公差 ≈ 5.0-5.5mm。**4.2mm 已被证明物理不可行（2026-11-16 核算），不再讨论。**

### C.10 接口、调试与维修

- 调试：原型走 USB 串口；商业化预留测试焊盘（不做外壳开孔）。
- 维修：卡扣 + 少量点胶，电池可更换（老人产品的电池衰减是 2 年后的主要客诉源）；底座 pogo 免插线降低老人操作难度。🟡 结构未开模。

## D. 软件与 AI 技术架构（软件 + AI 工程师）

### D.1 Android 端架构

模块划分（`core/transport/exec/plan/service/verify/data`）清晰，**FakeBleTransport 模拟链路 + 真机 GattBleTransport 双实现**是正确的工程决策——它让 95% 的逻辑在没有手机的情况下完成了测试。🟢

### D.2 哪些靠系统、哪些靠自研、哪些受限

| 能力 | 实现路径 | 限制 |
|-|-|-|
| 打开应用 | Android 标准 Intent（系统能力） | 无 |
| 拨打预设号码 | ACTION_DIAL（系统能力，跳拨号界面）或直接 CALL（需权限） | 建议 ACTION_DIAL，更安全 |
| 返回上一页 | 无障碍服务 AccessibilityService（自研+系统 API） | **受限**：需用户手动授权，国产 ROM 会重置（问题 4）；应用商店对滥用无障碍审核严格 |
| 读取屏幕内容 | 无障碍 | **本项目永久不用**（隐私红线） |
| 语音识别（命令词） | ESP-SR（设备端，乐鑫官方库） | 只能识别注册词，听不懂任意句式 |
| 任意句式理解 | L2 端侧小模型 / L3 云端（自研接入） | 未启动；L3 需要网络和隐私合规 |
| 语音播报结果 | Android TTS（系统文字转语音能力） | 无 |

**重要认知纠偏**：AI 理解了意图 ≠ 手机能执行。执行只发生在"白名单动作 + 系统允许 + 结果可核验"三者交集里。这是本项目与"AI 万能助手"的本质区别，也是答辩时最该讲清楚的一句话。

### D.3 语音与模型选型（AI 工程师结论）

- L1 设备端：ESP-SR MultiNet7 命令词（已验证 3/3）。**它不是通用语音识别，是"口令表"**——只能听懂注册过的词。优点是离线、零延迟、零成本；缺点是词表外一律拒识。🟢
- L2 端侧（手机上）：SenseVoice-Small（ASR，约 250MB，方言覆盖好）+ Qwen3-0.6B int4（意图理解，MNN 推理框架）。🔴 未启动，**建议由真机拒识率数据驱动决策**——如果变体词表扩充后拒识率 <10%，L2 可以无限期推迟，省钱省功耗。
- L3 云端：Qwen3-Flash 主路 + 豆包灾备。🔴 远期，仅用于多步骤任务；接入即引入隐私合规义务（见 H）。
- 800ms 硬回退规则：L2/L3 超时直接回退 L1 结果，保证体验下限。🟢

### D.4 延迟预算

按住说话 → 设备识别 2.1-2.9s（已实测🔵）→ BLE 传输 <100ms → 手机执行 Intent 级 <500ms → 播报。**全链路目标 ≤4s**，其中大头在设备端识别，可接受（老人场景对 1-2 秒差异不敏感，对"没反应"敏感——所以反馈必须即时：按下即"叮"）。

### D.5 数据存储与隐私

- 执行记录 JSONL 落盘本地，Lab 监测站读取；**当前无云端上传**。🟢
- 语音：按住才录、设备端识别后即弃，不上传（L3 启用前成立）。🟢
- 号码安全：预设号码存 App 本地，不进 BLE 协议帧、不进日志。🟢（设计决议）

## E. 外观设计与内部结构（工业设计师 + 硬件）

### E.1 尺寸合理性

68×56×5.5mm：长宽不超手机背板（主流手机宽 70-76mm），厚度约手机 2/3。5.5mm 是堆叠物理下限（C.9），**4.2mm 方案已被否决**。🟢

### E.2 外观概念图 vs 内部结构冲突检查

评审组逐项核对，发现以下冲突/风险：

| 检查项 | 结论 |
|-|-|
| 概念图中"一体无缝全铝"观感 | ⚠️ 冲突：铝必须只做正面盖，背壳必须塑料（天线+磁铁嵌槽）。渲染图需体现"铝面+塑料中框"的双材质拼接线，否则开模时必翻车 |
| 凹槽按键 + 围堰 | ✅ 与结构兼容（局部加厚 0.2mm + 支撑框方案已有）；1.2m 跌落测试列入手板验证 |
| 无灯缝 | ✅ 主键透光替代，LED 在键帽下方，空间可行 |
| USB-C 开孔位置（底边） | ⚠️ 注意：USB-C 座 3.2mm 是整机最高点，开孔位置要避开花键/磁铁区 |
| 麦克风斜面开孔 | 🟡 声学未实测；开孔防水（口水/雨水）未设计，建议加疏水膜（成本 <¥1） |
| 磁吸 vs 手机无线充电/NFC | 🟡 引磁环避开线圈区的设计已有（66×38mm 椭圆环），但**主流机型兼容清单未实测**——风险真实存在（部分手机贴环后无线充电失效） |

### E.3 人机工程

- 控制岛布局（三键集中顶面上半区、距外轮廓 ≥8mm）✅ 符合拇指可达性。
- 按键低于表面 0.4mm + 围堰：防误触与"老人手指粗按不准"之间存在张力——**凹槽深度对手指粗的老人可能按不到底**。这必须在手板阶段用真实老人的手验证（双厚度手板的另一重意义）。🟡
- 重量目标约 30-40g（估算：铝盖 ~6g + 电池 ~8g + PCB/器件 ~10g + 壳体磁铁 ~12g），吸在手机上不明显。🟡 无实物称重。

### E.4 可制造性

- 铝盖 CNC + 阳极氧化：小批量可行（¥10-15/件估算），量大开模（4-10 万沉没成本）。
- 首年策略：3D 打印 + 喷漆手板验证，卖动再开模。🟢 正确决策。
- 维修：电池可换设计需在结构阶段预留拆解口——**当前渲染图未体现任何拆解缝**，开模前必须补。

### F.2 关键判断

- **能通过软件完成的**：词表扩充、COMMAND_DIAL、三重自检、BLE 配对加密——全部不需要换硬件。

- **必须额外实验的**：手板握持、OTA 天线、续航、磁吸兼容、老人可用性。
- **不需要为演示做的**：L2/L3、方言、云端——演示用 L1 三命令 + DIAL 足够，且"够用"本身就是卖点。

### G.2 定价与商业化障碍

- 定价：🔴 待决策（199-299 vs 首批 399 矛盾，见基线清单 #1）。评审建议口径：首批 399 元小批量验证价格上限，是**验证动作**不是定价结论。
- 最大商业化障碍排序（评审组共识）：
  1. **分发**：无障碍类 App 上架难，侧载依赖子女操作——好在买单人=安装人，可接受但要说清。
  2. **价值密度**：3 命令撑不起 399 元——预设拨号 + 周报 + 远程配置的服务化是解法（问题 6/12 决议）。
  3. **单品 LTV 低**：一次性硬件买卖 → 子女端年费服务（49-99 元）是远期选项，与"无月费"话术冲突待解决。
  4. **认证与开模的沉没成本**（7-15 万）vs 学生团队资金——**建议校内阶段完全不碰**，只做手板验证。

### G.3 校内评审阶段的正确姿态

**不要讲商业模式画布，讲验证计划**：我们假设值 399 元、假设老人学得会、假设子女愿意装——然后用三个实验（手板握持、真机演示、社区试用）去证伪。**投资人最反感学生项目空谈市场规模，最欣赏"我知道自己不知道什么"。**
