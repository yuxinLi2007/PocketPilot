## 一、产品定位

| 项 | 内容 | 标注 |
|-|-|-|
| 一句话定位 | 吸在老人手机背面的实体语音按键：按住说一句话，手机把事办了 | 🟢 |
| 产品本质 | **"受约束的手机 Agent"**——只做预编排短路径（开应用、拨号、导航回家、返回），不做跨 App 自主操作（2026-11-11 辩论后修正，替代早期"完整手机 Agent"的表述） | 🟢 |
| 目标用户 | 使用者：65 岁以上、触屏操作困难的老人；买单人：子女 | 🟢 |
| 核心痛点 | 老人不会/不敢操作智能手机（找图标难、流程多步、怕按错）；子女远程当"电话客服"负担重 | 🟢（痛点为产品假设，**无正式用户调研数据**，见矛盾清单 #6） |
| 差异化三支柱 | ① 零唤醒（按住即说，不用喊唤醒词）② 高频命令离线可用 ③ 实体大键 + 方言兜底 | 🟢（其中"方言兜底"🟡，见矛盾清单 #3） |

### 2.3 关键架构决策（已定）

- 三层执行体系：标准 Intent → 应用公开 API → 无障碍严格受限 🟢
- 三层语音架构：L1 设备端命令词（ESP-SR MultiNet7）→ L2 App 端侧小模型 → L3 云端大模型；**800ms 硬回退**（L2/L3 超时直接回退 L1 结果）🟢
- BLE GATT 自定义 UUID（"pocket-pilot" 前缀），JSON UTF-8 `\n` 分帧，MTU-3 分片 🟢
- **财产安全是产品定义级红线**：任何版本不提供支付/转账能力，六层防守全部落地代码 🟢

## 四、当前真实进度（一句话版）

**设备端链路（按键→识别→蓝牙发送）在开发板真机上已闭环；手机端各模块在模拟器/PC 上已闭环；两者之间的"真机端到端"尚未接通——这是当前唯一的最大缺口（缺实体安卓手机）。**
