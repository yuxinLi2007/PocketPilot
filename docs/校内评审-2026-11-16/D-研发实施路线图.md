# D. 研发实施路线图（评审版 v1.0）

> 日期：2026-11-16 ｜ 原则：**严格串行、依赖优先**——关键路径只有一条：P0（不依赖硬件的软件工作）→ P1（真机端到端，唯一瓶颈）→ P2（真人验证）→ P3（演示工程化）。商业化实验（P4）与校内汇报弱相关，放最后。
> 周期为相对周次（W1 = 下周起算），因汇报截止日期未知，请按实际倒排。

## P0：软件收尾与口径冻结（W1-W2，纯软件，现在就能做）

| 项 | 内容 |
|-|-|
| **目标** | 把"承诺了但没写"的首版核心功能补齐到模拟器可演示状态；消灭文档矛盾 |
| **具体任务** | ① COMMAND_DIAL 协议 + App 执行器（ACTION_DIAL，号码存本地不进协议帧）② 词表扩充：每命令 10-20 条口语变体，**含预设联系人称呼（"打给女儿""打给儿子"等）注册为命令词，语音与物理预设键路由到同一 COMMAND_DIAL** ③ App 三重自检（无障碍/后台锁定/BLE 断连）+ SELF_CHECK 事件写入 ④ 应用商店无障碍政策桌面调研 ⑤ "PocketPilot" 商标检索 ⑥ 替换 README 旧渲染图（单键旧版→三键新版） |
| **所需资源** | 现有开发环境；无需新硬件 |
| **实施方法** | 全部先在模拟器+纯 Java 自测闭环；每个功能配回归用例 |
| **预期成果** | 4 命令（含 DIAL）模拟器全通；自检事件在 Lab 可见；政策与商标结论各一页 |
| **验收标准** | 模拟器回归全 PASS（含 DIAL 新增用例）；财产防线回归保持 120/0；矛盾清单 9 项全部关闭或标注 |
| **可能的问题** | DIAL 在部分 ROM 的拨号界面差异 → 用 ACTION_DIAL 而非直接呼出规避 |
| **进入下一阶段条件** | 实体安卓手机到位（**这是唯一硬门槛，现在就该解决**） |

## P1：真机端到端打通（W3-W4，关键路径，唯一瓶颈）

| 项 | 内容 |
|-|-|
| **目标** | 真实安卓手机 ↔ 开发板 BLE 双向全链路贯通 |
| **具体任务** | ① 真机 BLE 连接/订阅/分片写/状态回传 ② T0 平台穿刺 18 项 ③ 配对重连 10 项 ④ GattBleTransport 断线重连实测 ⑤ 三命令端到端（含 CONFIRMED 回传）⑥ 后台存活实测（静置 24h 断连率）⑦ TTS 播报链路 |
| **所需资源** | 实体安卓手机 1 台（建议借用或二手千元机，Android 12+）；开发板 |
| **实施方法** | 按已备好的测试记录表逐项打钩；失败项当日记录当日修 |
| **预期成果** | 真机端到端测试报告（附录屏）；断连率数据；广播到执行的实测延迟分布 |
| **验收标准** | 三命令真机各 10 次成功率 ≥90%；断连自动恢复；CONFIRMED 真实回传（不接受 UNCONFIRMED 充数） |
| **可能的问题** | 某 ROM 的 BLE 栈兼容性问题 → 记录机型清单，问题机型如实列入报告而非回避 |
| **进入下一阶段条件** | 端到端成功率达标 |

## P2：真实用户与可用性验证（W5-W6）

| 项 | 内容 |
|-|-|
| **目标** | 用真人（65+）证明"老人真的能用"，补上痛点证据缺口（风险 R9） |
| **具体任务** | ① 5-10 位老人访谈（痛点原话采集）② 老人实操测试：每命令 10 次，记录识别率/握持/手抖情况 ③ 手抖宽容窗参数调优 ④ 演示铁律验证："飞行模式+65 岁真人+不教措辞"完整走一遍 ⑤ 识别失败日志收集（为词表扩充/L2 决策供数据） |
| **所需资源** | 老人志愿者（家人/社区/养老院渠道）；开发板+真机 |
| **实施方法** | 不教学、只观察、记录卡壳点；访谈提纲提前备 |
| **预期成果** | 可用性测试报告（成功率、失败模式分类、原话引用 ≥3 条） |
| **验收标准** | 识别率 ≥85%；≥70% 老人无需第二次教学即可完成 3 命令 |
| **可能的问题** | 找不到足够老人 → 社区活动中心/家人亲友是最快渠道；样本小就如实说小 |
| **进入下一阶段条件** | 有可用于汇报的真实数据（哪怕样本小） |

## P3：演示工程化与汇报材料（W7-W8）

| 项 | 内容 |
|-|-|
| **目标** | 把技术成果转化为"专家看得懂、挑不出错"的汇报 |
| **具体任务** | ① 现场演示剧本（含断网/拒识/拦截三个"故意的失败演示"——展示系统可靠性比只展示成功更有说服力）② 演示视频备份（防现场翻车）③ 测试数据可视化（Lab 截图/成功率/延迟分布）④ PPT 按《F-最终产品介绍文案》制作 ⑤ 答辩问题库（E 文档）模拟演练 ≥2 轮 |
| **所需资源** | P1/P2 全部成果 |
| **验收标准** | 演示全流程彩排 3 次零失误；问答演练覆盖问题库 80% |
| **可能的问题** | 现场蓝牙环境复杂 → 提前到场测射频环境，视频备份兜底 |
| **进入下一阶段条件** | 汇报完成 |

## P4：商业化验证实验（汇报后，按需启动）

| 项 | 内容 |
|-|-|
| **目标** | 验证"能不能造出来、卖不卖得动" |
| **具体任务** | ① 双厚度手板 3D 打印（4.2/5.5）+ 老人握持测试 ② 铝盖手板 OTA 天线实测（掉值 <5dB 门槛）③ 深度睡眠固件 + 续航实测（≥5 天）④ 磁吸兼容清单实测（≥3N、无线充电/NFC）⑤ BOM 询价复核 ⑥ 小批量预售验证付费意愿 |
| **所需资源** | 手板预算 ¥500-2000；3D 打印渠道；时间 4-8 周 |
| **验收标准** | 形态方案验收口径逐项通过；预售转化率有数据 |
| **进入下一阶段条件** | 双实测通过 → 锁厚度 → 才讨论开模与认证（SRRC/CCC/BQB，前 4 个月启动） |

```
   │                 ▲                                    │
   └── 不依赖手机，先行 ──┘（手机到位是唯一硬门槛）              └── 汇报成功后才值得投入
```
