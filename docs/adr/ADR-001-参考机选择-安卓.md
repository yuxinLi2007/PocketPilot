# ADR-001 参考机选择：安卓

- **状态**：已采纳
- **日期**：2026-10-28
- **决策人**：项目负责人
- **关联**：`PocketPilot-最小原型验收标准与开发流程.md` v1.5 ／ `PocketPilot-iPhone语音操控方案.md` v0.1（暂缓）

---

## 背景

PocketPilot 的最小原型要验证"物理按键 + 语音 → 手机执行动作"这条链路。
执行层依赖系统级能力（返回、回桌面、跨 App 点击、读界面），两个平台的开放程度差距很大。
必须在开工前锁定一台参考机，否则验收标准无法固定，测试数据也无法横向比较。

## 决策

**本轮以一台安卓手机作为唯一参考机**（Android 12 及以上，RAM ≥ 6 GB）。
iPhone 不纳入本轮验收范围；`iPhone 语音操控方案` 作为技术储备保留，暂不投入开发。

## 备选方案

| 方案 | 结论 | 主要原因 |
|---|---|---|
| A. 安卓单平台 | **采纳** | 能力上限最高，开发与调试闭环最短 |
| B. iPhone 单平台 | 否决 | 无系统级自动化能力；App 编译需 macOS，当前为 Windows 环境 |
| C. 双平台并行 | 否决 | 人力只有一人，双平台会让每个阶段工期翻倍且都做不深 |

## 理由

1. **能力上限**：安卓 `AccessibilityService` 可发系统级返回/主页、读界面节点、跨 App 点击；iOS 无等价开放接口，C 档能力无法交付。
2. **开发环境**：iOS App 必须 macOS + Xcode 编译，当前无 Mac；安卓在 Windows 上可完成全流程。
3. **调试闭环**：adb 提供截图、日志、录屏、模拟点击，Codex 可直接读取这些证据做判断；iOS 链路长且需开发者账号。
4. **迭代成本**：安卓改一版 APK 几分钟；iOS 免费签名 7 天失效，需反复重装。
5. **风险可控**：参考机可用二手机，刷坏不心疼。

## 后果

**正面**
- L2（跨 App 自动化、确认页、全局停止）可完整实现与验收。
- 单人 + Codex 的迭代节奏可控，20 个工作日内能出结论。

**负面**
- 放弃 iOS 用户；若产品最终要上 iPhone，L2 执行层需要重写，且功能会缩减到 A/B 档。
- 安卓碎片化风险转移到"选机"上，必须用一台固定机型做基线。

## 复核条件

出现以下任一情况，重新打开本决策：

1. 目标用户中 iPhone 占比超过 70%——那说明产品定位本身要改，不是换台机器能解决的。
2. 参考机上无障碍服务无法稳定运行（被 ROM 强制回收）——**重新选安卓机型，而不是换平台**。
3. L2 验收完成后要评估 iOS 版本——届时以 `PocketPilot-iPhone语音操控方案.md` 为起点重做，不复用执行层代码。

## 补充（2026-10-28 实机）

- 参考机口径：**市面主流安卓手机**（Android 12+，RAM ≥ 6 GB），不指定具体型号；型号 / 系统版本 / ROM 在 T0 测试时记录，**不阻塞开发**。
- 板载 USB 已实测枚举为 `VID_303A&PID_1001`（ESP32-S3 原生 USB-Serial/JTAG）。USB OTG 实验在硬件上可行，但本轮仍以 **BLE HID 为唯一验收路径**，USB 只负责供电、烧录和日志。
