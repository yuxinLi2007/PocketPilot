# 板载麦克风采集验证（ESP32-S3-EYE / COM5）

记录时间：2026-10-30
固件：`artifacts/pocketpilot_ble.bin`（SHA256 `51890801C11A7886E9777365CBA5E92F2328EBC9ED42F0C83DCB146C69012183`）
硬件：ESP32-S3-EYE，板载数字 MEMS 麦克风（I2S：BCLK=GPIO41，WS=GPIO42，DIN=GPIO2）

## 1. 结论

| 项目 | 状态 | 证据 |
| --- | --- | --- |
| I2S 初始化与 DMA 读取 | **通过** | `PP_MIC_READY i2s_rate=48000 out_rate=16000 decim=3 format=24in32 bytes_per_sample=3` |
| 24 bit 样本字节对齐 | **通过** | 原始字节 `e4,e6,ff → le24=0xffe6e4 → pcm16=-26`，符号扩展正确 |
| 静音基线稳定、无削顶 | **通过** | 5 s 静音：`ac_rms=34 peak=195 p2p=374 dc=0 clipped=0` |
| **对真实声音的响应** | **通过** | 拍手实测：基线 rms 42，最响 0.5 s 窗口 rms 481（11.5x），单样本峰值 7669（满量程 32768） |
| 语音识别（ESP-SR） | **尚未验证** | 未接入模型，本文件不涉及 |
| WAV 人耳试听 | **尚未验证** | 本轮以电平统计判定，未做回放试听 |

明确边界：本节只证明“声音 → 数字 PCM”的采集链路可用，**不证明**语音识别、命令词命中率或端到端时延。

## 2. 修复的根因

原实现把 I2S 配置为 `32BIT` 数据宽度，却按 `int32_t` 读取官方 BSP 的 24 bit 数据，导致 DMA 中样本边界错位，表现为“有电平但与人声无关”的噪声。

现按官方 BSP `esp32_s3_eye_idf5.c` 对齐：

```c
.data_bit_width = I2S_DATA_BIT_WIDTH_24BIT,
.slot_bit_width = I2S_SLOT_BIT_WIDTH_32BIT,
.slot_mode      = I2S_SLOT_MODE_MONO,
.slot_mask      = I2S_STD_SLOT_LEFT,
.ws_width       = 32,
.bit_shift      = true,
.left_align     = true,
```

ESP-IDF 在 24 bit 数据宽度下按 **3 字节/样本**组织 DMA，代码据此小端还原 24 bit、符号扩展、右移 8 位得到 16 bit PCM；采样启动后丢弃 400 ms，两段式测试第二段前再丢弃 300 ms，消除启动瞬态。

## 3. 测试过程与结果

| # | 测试 | 结果 | 说明 |
| --- | --- | --- | --- |
| 1 | 原始样本转储（`r`） | 通过 | 32 个样本，`empty_reads=0`，三字节结构与符号位正确 |
| 2 | 静音 5 s（`m`） | 通过 | `ac_rms=34 peak=195 dc=0 clipped=0`，无满量程瞬态 |
| 3 | 电脑扬声器 1 kHz 测试音（`t`） | **失败** | 安静 rms 33 / 出声 rms 23，判定 `level_does_not_respond_to_sound`；但无法确认测试音真的从扬声器播出，故只能记为“测试方法不可靠”，不能判定硬件损坏 |
| 4 | 90 s 实时电平监看（`l`） | **失败（无效样本）** | 记录期间无人发声：基线 rms 48、最高 165、0 个窗口超过阈值；属于“没做声”而非“麦克风坏” |
| 5 | 声学实测（拍手 + 说话，`l` + `tools/mic-live-watch.py`） | **通过** | 见下表 |

### 3.1 声学实测数据（2026-10-30 08:54，共 142 个 500 ms 窗口）

`rms` 为去直流后的交流有效值（16 bit 量纲），`peak` 为窗口内单样本绝对值峰值。

| 时间 (s) | rms | peak | 判读 |
| --- | --- | --- | --- |
| 18.0–20.5 | 23–48 | 108–264 | 环境本底 |
| 21.0 | 180 | 4269 | 第 1 次拍手 |
| 21.5 | 162 | 2668 | 拍手尾音 |
| 22.5 | **481** | **7669** | 第 2 次拍手（本段最响） |
| 24.5 | 293 | 5175 | 第 3 次拍手 |
| 27.5–28.0 | 141–198 | 2404–3706 | 说话“打开地图” |
| 29.5 | 168 | 2519 | 说话尾音 |
| 31.0–31.5 | 127–135 | 489–649 | 余音 |

统计：中位 rms 42，p90 119，最大 481；判据 `max(3 x 基线, 400) = 400`，实测 481 达标。

关键点：电平**只在该时间窗内**抬升，其余时间回落到 20–50，说明采集到的是真实声学事件，而不是恒定噪声或启动瞬态。

## 4. 复现方法

```powershell
cd 'D:\个人项目\firmware\pocketpilot_ble'
$env:PYTHONIOENCODING='utf-8'

# 实时电平监看：每次触发 90 s，脚本自动续采；出声即可
python tools\mic-live-watch.py --port COM5 --total-seconds 120
```

固件串口命令（115200）：

| 命令 | 作用 |
| --- | --- |
| `l` | 连续采集 90 s，每 500 ms 打印 `PP_LEVEL t=..ms rms=.. peak=..` |
| `t` | 两段式：3 s 安静 + 3 s 出声，打印 `PP_MIC_VERDICT` |
| `w` | 以二进制流输出 5 s 16 kHz PCM，供 PC 拼 WAV |
| `m` | 采集 5 s 并打印 `PP_MIC_STATS` |
| `r` | 打印 32 个原始三字节样本，检查字节序与符号位 |
